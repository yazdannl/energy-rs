# GAPS — places the current decision core can silently do nothing

This is the "never silently idle" audit that feeds the rewrite. It lists current code paths where a
decision is skipped, an error is swallowed, or the emitted diagnostic is indistinguishable from
`nothing happened`. References follow `SPEC.md`: unprefixed = `main @ 0c3e7a0`, `0.15.9:` =
`release/0.15.9` (the live branch). A path is included even when 0.15.9 already fixed it on `main`,
because the rewrite must not reintroduce it.

Severity: **P0** = leaves energy uncontrolled or misreports delivery; **P1** = hides a real fault or
loses evidence; **P2** = confusing but recoverable.

---

## A. Planning and horizon (silent no-plan / wrong-plan)

1. **P0 — Incomplete price coverage is silently truncated.** `0.15.9:crates/energy-core/src/plan_source/live.rs:261-289`: `horizon_slots` breaks at the first uncovered quarter-hour; the plan simply becomes shorter and no `degraded` field records the missing slots. A 20-slot plan looks like a valid plan. Rewrite: typed `insufficient_price_coverage` with first missing `t_start`.
2. **P0 — Solar headroom over the whole horizon can zero every cheap grid charge.** `0.15.9:crates/energy-core/src/plan/clamp.rs:96-110,155-175`: future PV surplus is subtracted from tonight's charge ceiling regardless of intervening discharges. The 15:47Z incident produced `chargedWh=0`, zero positive slots and a 0 W `reserve_hold` during a 0.35→0.53 tonight-to-tomorrow spread. Rewrite: delete the post-solve clamp; use per-slot curtailment `max(0, pv−load−charge−export_limit)·dt`, priced once, with unlimited export producing zero curtailment.
3. **P1 — A clamp can override the solver without failing the plan.** `0.15.9:crates/energy-core/src/plan/clamp.rs:126-151`: the floor repair and PV clipping rewrite `powers`; `plan/assemble.rs:117-136` only appends a reason slug, and `assemble.rs:43-44,62` hard-codes `gated_kwh = 0.0`. Rewrite: structured `unmet_kwh[]` and `binding_bounds[]`.
4. **P0 — `feasible` means "terminal target reached", nothing else.** `0.15.9:crates/energy-core/src/plan/assemble.rs:45-47`: `infeasible_reason` is set only when terminal error >0.05 kWh; no price gap, missing pack, cap conflict or maintenance shortfall can make a plan infeasible. Rewrite: feasibility aggregates all constraints.
5. **P0 — Unlimited netting sentinel.** `0.15.9:crates/energy-price/src/settlement/billing.rs:11-12,120-129`: absent budget means `1e9 kWh`, so export is priced 1:1 forever with no warning. Rewrite: `None` = unknown and requires a conservative price or explicit operator acknowledgement.
6. **P1 — Net-metering default is on.** `0.15.9:crates/energy-server/src/bootstrap/config.rs:191-201`: an unrecognised stored value silently becomes `On`; after 2027 a legacy contract could still be priced as netted. Rewrite: unknown regime is `Unknown`, never silently on.
7. **P1 — Forecast degradation is a free-text note.** `0.15.9:crates/energy-core/src/plan/plan_input.rs:34-36`, `plan/generated_plan.rs:28-30`: `degraded: Option<String>` carries the fallback reason; there is no structured freshness/source/coverage for a consumer to assert. Rewrite: typed degradation object.
8. **P1 — Forecast staleness check can be disabled by bad config.** `plan/checks.rs:41-56`: `limit = max(2×replan_seconds, stale_plan_seconds)`; both values come from the ledger with silent fallbacks (`0.15.9:crates/energy-server/src/bootstrap/config.rs:26-27,184-189`), so a huge configured replan accepts a day-old forecast. Rewrite: hard absolute upper bound.
9. **P1 — Empty grid statistics are only notices.** `0.15.9:crates/energy-core/src/plan_source/ha_series.rs:81-99`, `source_notice.rs:1-121`: the sum silently drops empty sources. The INFO/WARN is emitted once per state, but the plan's money basis can be wrong for a full interval before anyone reads it. Rewrite: plan must carry `grid_source_coverage` and refuse a sum with no source.
10. **P2 — Forecast capture is bucketed to hide churn.** `0.15.9:crates/energy-core/src/plan_source/live.rs:201-232`: `forecast_as_of.div_euclid(900)` suppresses a genuine forecast refresh inside a slot; combined with gap 12 below, a stale forecast can survive a slot.

## B. Replanning and mode (no trigger, no signal)

11. **P0 — `main` executes an old plan after a refused solve.** `engine/tick.rs:88-115`: `Err` from `source.plan` is logged and `maybe_replan` returns the original `stale` flag; for `SlotBoundary`/`SocDeviation` that is `false`. The old setpoint runs against fresh but unusable inputs. 0.15.9 fixed it (`0.15.9:crates/energy-core/src/engine/tick.rs:111-116`), rewrite must keep the hold.
12. **P0 — Persist failure does not stop plan use.** `engine/tick.rs:94-108` and `0.15.9:crates/energy-core/src/engine/tick.rs:127-145`: a failed `store_plan` is a `warn!`, the in-memory plan is installed anyway. The ledger/API then reports a different plan than dispatch uses. Rewrite: persist or hold.
13. **P0 — Maintenance journal failure silently aborts replan.** `0.15.9:crates/energy-core/src/engine/tick.rs:137-138`: `self.journal_maintenance(...).ok()?` returns `None` from `replan()` with no log; the caller sees "refused" and holds with no named cause. Rewrite: typed journal error.
14. **P0 — Poisoned plan-source mutex is "no change".** `0.15.9:crates/energy-core/src/plan_source/live.rs:217-231` and `:244-249`: lock failures return early or `Changes::none()`; a real price/forecast update is then never a replan trigger. Rewrite: `InputsUnavailable` trigger + hold.
15. **P1 — SoC deviation is silently disabled on bad telemetry.** `replan/trigger.rs:72-81`: when `capacity_kwh <= 0` or `energy_kwh` is non-finite, `soc_deviated` returns `false`. A pack with corrupt energy data cannot force a replan. Rewrite: `TelemetryUnavailable` trigger.
16. **P1 — Manual replan failure is discarded.** `0.15.9:crates/energy-core/src/engine/commands.rs:70`: `let _ = self.replan_now(now).await;`. The operator gets no result for an explicit action. Rewrite: command result is a typed reply.
17. **P1 — Refusal backoff is invisible in the plan API.** `0.15.9:crates/energy-core/src/engine/refusal_backoff.rs:7-19`: the tick holds while `now − refusal.at < backoff`, but no `refusalReason`/`retryAt` is surfaced. "Nothing happened" is indistinguishable from a healthy hold.
18. **P0 — Advisory can persist forever.** `mode.rs:3-31`, `safety/authority.rs:9-25`, `0.15.9:crates/energy-server/src/api/mode.rs:28-69`: advisory is a normal, persistent, API-selectable mode; ticks compute and write nothing indefinitely. Rewrite: 900 s `protection_active` session with visible expiry that returns to `auto` through a guarded transition; the M5 safety lane stays active throughout.
19. **P1 — Unknown mode is `dry_run` but unmarked.** `mode.rs:26-31`: the fallback disables economic writes yet emits no `unknown_mode_value` event, so a corrupt setting looks like an operator choice and protection can remain off. Rewrite: `protection_active` with safety active, `unknown_mode_value` and guarded expiry to `auto`.

## C. Dispatch and safety (holding is not self-explaining)

20. **P0 — Echo without flow was reported as verified.** 0.15.4 life: `inputLimit` echoed for 150 s with `gridInputPower=0` and unchanged SoC; memory `live-dispatch-fixes`, `cell-balance-charge-run`. 0.15.9 fixes the receipt (`0.15.9:crates/energy-battery/src/control/flow.rs:23-32,108-132`, `battery_sink.rs:155-182`) but `dispatch/dispatcher/write.rs:64-70` still returns `written=true` on `ReadUnverified` with no `flow_measured` and no applied value. Rewrite: every row has an evidence class.
21. **P0 — A read miss has an empty receipt.** `0.15.9:crates/energy-core/src/dispatch/battery_sink.rs:110-114`: `SinkError::ReadUnverified` returns no receipt; `dispatcher/write.rs:66-70` sets `written=true, verified=false, applied_w=0.0` by default. A consumer that ignores `flow_measured` reads "0 W delivered".
22. **P1 — Suppressed ticks can look like zero delivery.** `0.15.9:crates/energy-core/src/dispatch/dispatcher/backoff.rs:53-90`: `applied_w` is 0.0 with `flow_measured=false` when there is no fresh reading; the explanation text exists only in `error`. Rewrite: `flow_measured` is mandatory and surfaced in JSON.
23. **P1 — Readback streak resets on a missing reading.** `0.15.9:crates/energy-core/src/dispatch/readback.rs:39-42`: an absent pack reading returns `Readback::default()`, so a device that disappears after three non-compliant ticks restarts with a clean streak. Rewrite: missing reading is its own evidence state.
24. **P0 — Fault suppression can swallow safety traffic on 0.15.2-0.15.6.** `dispatch/dispatcher.rs:160-177` (`main`) sets `vector = reading.available && !backoff`; a latched 0 W cell-guard hold was suppressed during backoff (memory `cell-guard-enforcement`). 0.15.9 fixed both halves (`0.15.9:crates/energy-core/src/dispatch/pack_context.rs:76-97`,
  `0.15.9:crates/energy-core/src/dispatch/dispatcher.rs:189-213`); rewrite must keep the separate safety lane.
25. **P0 — Backoff can suppress the import-ceiling remedy.** Same as gap 24 for a guard discharge in older code; 0.15.9 uses `guarded` to bypass stale-zero and backoff (`0.15.9:crates/energy-core/src/dispatch/dispatcher.rs:165-194`). Rewrite: all safety traffic bypasses ordinary backoff, but never the pack's own physics.
26. **P1 — One `primary()` reason hides the rest.** `safety/decision.rs:60-77`: `reasons` is a vector but the report shows one primary. A `grid_import_limit + soc_floor + ramp_limit` block can appear as only the first reason. Rewrite: ordered complete reason vector.
27. **P1 — `grid_missing` blocks before binding reasons are computed.** `safety/finish.rs:12-19`: every other bound is omitted from the decision when telemetry is missing, so an operator cannot tell which additional constraint also applied.
28. **P1 — `lo > hi` blocks use insertion-order reasons.** `safety/finish.rs:52-95`: fallback `PowerClamp` when the list is empty names the wrong cause for a contradictory configuration. Rewrite: never empty; name the contradictory pair.
29. **P2 — Tiny setpoints silently become holds.** `dispatch/mod.rs:84-85`, `0.15.9:crates/energy-core/src/dispatch/dispatcher/write.rs:24-30`: ≤30 W becomes `sink.hold`; the intended watts are in `intended_w` but there is no `tiny_setpoint` reason. Rewrite: explicit reason and counter.
30. **P1 — Ramp conflicts are reported, not prevented.** `safety/ladder.rs:199-204`, `safety/finish.rs:20-50`: if requested power is outside `[previous−1000, previous+1000]`, the value is clamped/blocked but the stale previous measurement itself is not flagged. Rewrite: `ramp_baseline_untrusted` when the baseline is old.
31. **P1 — One bad pack does not fail plan delivery.** `0.15.9:crates/energy-core/src/engine/failure.rs:62-87`: unreachable packs get an orphan hold and the tick is `Ok`. Correct behavior, but the API has no `delivery.partial`/`failed_pack_ids`, so the plan looks fully delivered (memory `live-dispatch-fixes`, Diederik 09:42-09:47Z).
32. **P0 — Orphan holds are best-effort with no confirmation contract.** `engine/failure.rs:17-38,49-60`: `let _ = self.event(...)`, `unwrap_or_default()` on a poisoned lock, and `warn!` when `hold_all` fails. The packs we drove may keep their last setpoint and the log may contain nothing actionable.
33. **P1 — A faulted pack is deliberately left unheld.** `0.15.9:crates/energy-core/src/engine/failure.rs:71-74`: the orphan filter skips packs in backoff. This avoids a command storm but means "we own it, cannot see it, and are not holding it" is invisible in the report.
34. **P1 — Readback arm/pause locks ignore poison.** `0.15.9:crates/energy-core/src/dispatch/fault_guard.rs:52-64,80-115`: `lock().ok()` means a poisoned backoff map returns `None` — no blocker, no arm — so recommands resume silently. Rewrite: lock failure is a hold.
35. **P1 — Empty final vector is a no-op.** `0.15.9:crates/energy-core/src/dispatch/fleet_clamp.rs:20-25`: if no pack is in `vector`, `apply` returns `None` and the tick continues without a fleet-level reason. Rewrite: `no_commandable_pack` outcome.
36. **P2 — Prior-write `Unconfirmed` becomes silence.** `0.15.9:crates/energy-core/src/dispatch/battery_sink.rs:78-89`: `BatteryError::Unconfirmed` maps to `None` (no receipt) while a previous ramp continues; no row says "deferred because a command is in flight". Rewrite: `deferred_previous_command` receipt.
37. **P1 — Streaming status contradiction needs two reports.** `0.15.9:crates/energy-battery/src/control/flow.rs:30-32`, `0.15.9:crates/energy-core/src/dispatch/battery_fleet.rs:114-128`: one `outputHomePower=799` with charge status is tolerated; correct for hardware mapping, but if reports stop at one the contradiction never reaches the UI. Rewrite: include `contradiction_streak` in the pack row.
38. **P1 — `messageId` resync never confirms anything.** `0.15.9:crates/energy-battery/src/control/watch.rs:37-71`: forward jumps 33..128 are `Resync`, accepted as a new baseline but explicitly not evidence for the outstanding command. The command remains pending with no `resync_during_write` reason until the echo window expires.
39. **P1 — Freshness rejection is silent.** `0.15.9:crates/energy-battery/src/control/echo.rs:113-122`: a duplicate/older `messageId` makes `is_fresh` false; no event distinguishes "device is quiet" from "device is replaying".
40. **P1 — Wedge/restart can be overwritten by later reports.** `0.15.9:crates/energy-battery/src/control/watch.rs:74-98` detects them, but the fault is only carried in the observation path; if a consumer reads only limits it sees a healthy-looking pack.

## D. Learning and maintenance (silence disguised as up-to-date)

41. **P0 — Learning can skip every pack for 21 h and still look current.** `0.15.9:crates/energy-core/src/wiring/sessions.rs:117-145`: extraction uses a 1 h window and `completed_only` skips packs whose night run never closed; `0.15.9:crates/energy-core/src/engine/tick.rs:188-200` advances `last_session_check` regardless of how many reports came back. Live 2026-11-22: all four packs stale, diagnostics all zero, no `learning.applied` lines. Rewrite: durable extraction and per-pack consumption checkpoints advanced only after results are persisted, idempotent and restart-safe.
42. **P0 — Empty learning passes advance `updatedAt`.** `0.15.9:crates/energy-battery/src/learning/profile.rs:62-86` sets `updated_at = report.estimated_at`, and `efficiency.rs:206-227` re-stamps a kept previous profile with `now`. An operator sees a fresh timestamp on a 21 h-old measurement. Rewrite: `updatedAt` = last real measurement; `lastAttemptAt` = last pass.
43. **P1 — Skipped packs emit no named blocker.** `0.15.9:crates/energy-core/src/wiring/sessions.rs:129-144`: `continue` for `!just_finished` and `records.is_empty()`; the API (`0.15.9:crates/energy-server/src/api/packs.rs:122-146`) exposes `sessionsUsed` and diagnostics but no `lastAttemptAt`, `sessionsInWindow`, `sessionsComplete` or blocker list.
44. **P1 — Manual relearn is only a queue acknowledgement.** `0.15.9:crates/energy-server/src/api/learning.rs:38-63`: `202 {"accepted":true}`; no pass id, no completion callback. The 16:51Z manual recovery looked like a measurement in the UI before any measurable evidence existed.
45. **P1 — Efficiency refusals can be all-zero in the API.** `0.15.9:crates/energy-battery/src/learning/pair_diagnostics.rs:12-57` has all the counters, but when no pass runs they stay at their `Default` zero and are indistinguishable from a pass that saw nothing. Live 0.15.9 after days of 0 W dispatch produced 406/417 refusals per pack (289/297 `session_incomplete`, 95/98 `session_short`) from 0.0026 kWh micro-sessions — a data-shape failure that must be reported as `no_meaningful_cycle`, not as 400 measurement refusals.
46. **P1 — Corrupt learning profile JSON is silently ignored.** `crates/energy-core/src/wiring/learning_store.rs:42`: `serde_json::from_str(...).ok()` returns `None`, which the learner treats as "no previous profile"; a corrupt row resets the estimate to defaults without an event.
47. **P1 — Capacity pool prior silently drops weak or corrupt entries.** `0.15.9:crates/energy-battery/src/learning/capacity.rs:116-117`: `prior.filter(confidence ≥ 0.20)` falls back to the label with no diagnostic; `usable_samples` at `:183-200` drops implausible samples without exposing their ids in `LearningReport.refused`.
48. **P1 — Maintenance assignment slot can vanish without a reason.** `0.15.9:crates/energy-core/src/maintenance/apply.rs:21-29`: `let Some(slot) = ... else { continue; }`. A replan that shortens the horizon drops a due pack's charge with no `unassigned` row.
49. **P0 — Maintenance journal errors are swallowed.** `0.15.9:crates/energy-core/src/maintenance/progress.rs:71-74,123-125,146-149`: `abort_dwell`/`begin_dwell`/`finish_dwell` errors are `warn!`; `finish` returns `None`, so a completed balance that could not be stamped looks like "still balancing" forever.
50. **P1 — Maintenance history read failures look like "not due".** `0.15.9:crates/energy-core/src/maintenance/ledger_history.rs:26-37,56-57`, `port.rs:71-74`: chains of `.ok()?` and `unwrap_or_default()` turn a failed ledger read into an empty due list with no refusal.
51. **P1 — Dwell can be abandoned by a missing assignment.** `0.15.9:crates/energy-core/src/maintenance/progress.rs:33-55`: when the plan that started a dwell disappears, the code abandons it with `assignment_lost`. Correct safety, but if the plan was lost silently (gap 11-13) the operator sees only `assignment_lost`.
52. **P2 — Maintenance price band anchor is process-local.** `0.15.9:crates/energy-battery/src/protection/full_charge/assignment.rs:28-31` and memory `full-charge-partial`: the band ceiling is carried in `MaintenancePort`, so a restart silently resets the anchor and can demote an already-booked slot.

## E. Cross-cutting diagnostics

53. **P0 — `written`, `verified` and `flow_measured` are three different facts but not all consumers read them.** `0.15.9:crates/energy-core/src/dispatch/pack_report.rs:5-45`: the struct documents the distinction; a log line built from `written` alone still reads "command applied" for `ReadUnverified`. Advisory rows also set `applied_w = 0` (`dispatch/mod.rs:3-13`), which can be mistaken for measured zero when an old command is standing. Rewrite: one `evidence` enum is the required primary field and `applied_w = null` whenever no fresh measurement exists.
54. **P1 — JSON summary serialization failures become `{}`.** `0.15.9:crates/energy-core/src/plan/plan_summary.rs:60-64`: `unwrap_or_else(|_| "{}")`. A plan row then has no summary and no error event.
55. **P1 — Many lock failures are intentionally ignored.** `crates/energy-core/src/engine/tick.rs:218-223` (`let _ = self.mark(now)`), `0.15.9:crates/energy-core/src/engine/tick.rs:129,250`, `0.15.9:crates/energy-core/src/engine/failure.rs:18-27,32-38,53`: watchdog marks, events and owned-pack reads all drop errors. A stalled engine can still look alive until the next layer notices.
56. **P1 — Best-effort holds with no receipt are still "done".** `0.15.9:crates/energy-core/src/engine/failure.rs:31-38,57-59,78-85`: `hold_all` failure is logged but the tick returns success. Rewrite: delivery status is part of `TickOutcome`.
57. **P2 — Default-on/off choices in config hide operator intent.** `0.15.9:crates/energy-server/src/bootstrap/config.rs:20-48,127-143`: unreadable numbers fall back to shipped defaults for power, reserve and maintenance intervals, with no `config_fallback` event. A typo and a deliberate default are indistinguishable.

## F. Contract gaps found in reviewer pass (2026-11-22)

58. **P0 — The real defect is a missing cheap-night charge, not a skipped equally priced today peak.** Verified prices: today's maximum was 0.4188 at 18:00Z; tomorrow 15:45–18:00Z is 0.5088–0.5303; tonight is 0.3980→0.3498. Holding today is correct. The serious failure is that the plan refuses tonight's 0.3498 charge for tomorrow's 0.5303 sale, leaving the fleet idle for days and giving the efficiency learner no cycle. The earlier 6.4 kWh comparison used tomorrow's prices as today's and was chronologically infeasible from 89 % SoC; the replacement fixture is 5.0 AC kWh with equal final energy and exact slot prices, revenue B 2.568660 EUR and delta +0.514660 EUR (`0.15.9:crates/energy-core/src/plan/clamp.rs:96-175`, `0.15.9:crates/energy-opt/csrc/core_solver.c:357-374`).
59. **P0 — C-core ties are resolved by ascending action order, not time.** `0.15.9:crates/energy-opt/csrc/core_solver.c:309-313,445-455,462-483`: backward DP uses strict `<` on sorted powers and reconstructs from the nearest grid point's `argmin`. When two peaks are genuinely equal, calendar preference is undefined. Rewrite: documented lexicographic tie-break with the earlier slot first.
60. **P0 — Solar headroom was a hard post-solve cut.** `0.15.9:crates/energy-core/src/plan/clamp.rs:126-175`: the cut can invalidate the optimized path and the floor repair rewrites power without marking an unmet obligation. Rewrite: priced per-slot PV-spill term; hard physics only.
61. **P0 — A below-floor/above-ceiling target conflict can still produce a below-floor target.** `0.15.9:crates/energy-core/src/plan/config.rs:61-64` applies `max(soft,floor).min(ceiling)` without checking `floor ≤ ceiling`. Rewrite: reject `InvalidBounds` before solving.
62. **P0 — The terminal penalty is two-sided.** `0.15.9:crates/energy-opt/csrc/core_solver.c:420-422` charges `target_penalty×|e−target|`, so ending above a minimum target is penalised. Rewrite: one-sided `max(0, target−e_end)` and minimum semantics.
63. **P0 — Emergency charge can be blocked by ordinary constraints.** `safety/ladder.rs:83-96`, `safety/finish.rs:12-19`: authority, plan tracking, ramp, grid telemetry and import bounds sit in front of the cell latch; a missing meter can block the whole pack. Rewrite: cell actions bypass those gates, but never pack physics; impossible emergency emits a typed fault.
64. **P0 — Orphan/cancel/restart transitions do not require verified neutral writes.** `engine/failure.rs:17-38,49-60` uses best-effort `let _` and `warn!`; `0.15.9:crates/energy-battery/src/control/watch.rs:37-71` treats 8-bit jumps as resync without confirming the outstanding command. Rewrite: explicit verified 0 W, separate receipt state, immediate safety precedence.
65. **P1 — Recovery after refusal is invisible and unrecoverable without a new input change.** `0.15.9:crates/energy-core/src/engine/refusal_backoff.rs:7-19` holds but never publishes `retryAt`, and `0.15.9:crates/energy-core/src/engine/commands.rs:70` drops manual replan failures. Rewrite: 90/180/300 s ladder, visible refusal/retry, same policy for tick and command replans.
66. **P1 — Stored plan can remain eligible after a failed replan.** `engine/tick.rs:88-115` continues the previous plan; stored plans are not separated from live results. Rewrite: invalidate on failure; only a freshly solved, persisted plan is executable.
67. **P1 — Capacity prior includes the pack being learned.** `0.15.9:crates/energy-battery/src/learning/pool.rs:37-53` pools every batch, including the target pack, so a shallow 21 h-stalled pack can reinforce its own stale number. Rewrite: exclude self, weight by span and recency, cap pool confidence at 0.85.
68. **P1 — Micro-sessions inflate refusal counters.** Live 0.15.9 pack diagnostics: 406/417 candidates refused, with 289/297 `session_incomplete` and 95/98 `session_short`, because days of 0 W dispatch left 0.0026 kWh, SoC 16→16 runs. `0.15.9:crates/energy-battery/src/learning/session.rs:8-12,65-87` classifies them individually instead of discarding them as `idle_blip`. Rewrite: prefilter at 50 W/0.15 kWh and emit `no_meaningful_cycle`.
69. **P1 — Efficiency pairing has no explicit no-reuse or refusal barrier contract.** `0.15.9:crates/energy-battery/src/learning/pairing.rs:28-82` and `blocks.rs:65-117` implement blocks, but the rewrite contract must forbid block reuse, define minimum energies/spans, 7-day gap, hold-drift and closure bounds, and state that capacity and efficiency cannot veto each other.
70. **P1 — Maintenance due anchor is process-local.** `0.15.9:crates/energy-battery/src/protection/full_charge/assignment.rs:28-31` keeps the band anchor in `MaintenancePort`; a restart can reset it and drop a partial fill. Rewrite: persisted due time, `missing_kwh` carryover, idempotent completion.

71. **P0 — Price provenance was lost.** An earlier analysis labelled tomorrow's 0.5088–0.5303 prices as today's; direct add-on prices show today's maximum 0.4188 at 18:00Z and the 16:00–17:45Z slots at 0.4037–0.4130. Any future rewrite must carry slot timestamp, source and regime with each price so a mislabelled day cannot drive an acceptance test. Rewrite: `SPEC.md` verified fixture and S115 counterexample.
72. **P1 — Overlapping PV-headroom windows would double-penalise one forecast.** A window sum `Σ spill_price_i·spill_i` counts the same prospective shortage in many slots and can swamp a profitable cycle. Rewrite: one curtailment account per slot, `curtail_kwh=curtail_kw·dt`, with no second-pass feedback.
73. **P1 — “Foregone export” is not a loss under unlimited export.** A full battery does not prevent PV export when export is unlimited, and the grid objective already earns that revenue. Rewrite: penalise only physically curtailed PV; `export_limit=0` maps to `+∞`, not zero headroom.
74. **P1 — Site limits were listed but not imposed.** `0.15.9:crates/energy-core/src/plan/config.rs:19-34` leaves solver import/export unbounded and relies on later clamps. Rewrite: hard inequality `−export_limit ≤ load−pv+p ≤ import_limit` in every slot, with infeasibility when battery and site windows do not intersect.
75. **P1 — Terminal salvage overvalued stored energy.** `0.451852 EUR/stored kWh` from `cheapest/η_rt + wear` exceeds the 0.388667 replacement cost, creating an end-of-horizon accumulation incentive. Rewrite: `salvage=cheapest_buy/η_c`, wear only on actual discharge, with a terminal-behaviour test.
76. **P1 — Tie-break left enumeration order decisive.** “Energies to 1 Wh” was prose only and distinct schedules could tie on every published key. Rewrite: canonical six-key ordering including quantized state and power signatures, no-discharge index 120, and no provisional-discharge pass feeding back into the objective.

77. **P0 — Curtailment and site bounds contradicted each other.** A bound using uncurtailed PV forces charging/infeasibility, while a separate “avoided curtailment” benefit pays the same kWh twice. Rewrite: `g = load − (pv − c) + p`, `0 ≤ c ≤ pv`, hard `−export_limit ≤ g ≤ import_limit`, and no separate curtailment price; grid revenue prices the actual flow once.
78. **P1 — A range was used as a constant in the acceptance fixture.** Tomorrow's verified quarter-hour prices run 0.4790–0.5303; using flat 0.5303 inflated revenue B by 0.082840 EUR. Rewrite: S122 names every slot used and recomputes 2.568660 EUR.
79. **P1 — Fixture timestamps crossed midnight without a date change.** A recharge labelled 22 Nov 00:45–01:00Z preceded the 22 Nov 15:45Z start, and the 0.2 kWh sale had no slot after 17:15. Rewrite: explicit start/end, 23 Nov 00:45–01:00Z partial recharge and 17:30–17:45Z partial sale with energy balances after every transaction.

80. **P0 — A safety regression had removed dry_run's no-write guarantee.** Earlier revision let safety writes through in `dry_run`; the owner relies on dry_run never touching hardware. Rewritten invariant: a persisted `dry_run` is honoured as the write-free `dry_run_persisted_write_free` state, operational entry requests are rejected, and nothing starts writing.
81. **P0 — Import protection was allowed to ignore physical limits.** “Limited only by SoC floor and cell latch” could authorize unsafe discharge. Rewrite: universal physical limits bind every safety action; blocked outcome names the limit.
82. **P1 — Restart grace could leave a standing nonzero command.** “No command standing assumed” had no verification predicate. Rewrite: two fresh neutral reports or a verified neutral write, then grace expiry/escalation.
83. **P1 — Mode and cadence rules were internally contradictory.** Invalid config expired into auto; solve-success deadline was stated as a guarantee; plan eligibility ended exactly at replacement due time. Rewrite: protection-active invalid-config state, attempt-vs-success distinction, `t_due+5s` ordering.
84. **P1 — Learning publication rules mixed candidate and metric states.** One accepted pair appeared to publish a round trip despite a three-pair minimum; capacity clamp and bounds_rejected overlapped. Rewrite: candidate vs published separation, explicit prior freshness, thresholds, clamping and reproducible formulas.

85. **P0 — A time-overlap cursor cannot discover late completions.** A 900 s extraction overlap misses a session closing hours later, and start-time ordering places it behind an advanced cursor. Rewrite: durable open-session and completion-event log, completion events consumed by `(completed_at,event_id)` with exactly-once `event_id` deduplication.
86. **P0 — The efficiency closure correction had the wrong sign.** A positive `δ` means energy was retained, so subtracting it understated round-trip efficiency. Rewrite: `η_raw=(O+δ·C_eff/100)/I`, exact equal-leg quadratic, two worked examples and rejection before clamping.
87. **P1 — Efficiency aggregation was undefined.** Weights and thresholds existed but not rejection order or whether counts preceded outlier removal. Rewrite: seven-step order, post-rejection inlier counts, weighted median and MAD.
88. **P0 — Out-of-range raw efficiency could be clamped into publication.** A raw 0.35 became 0.50. Rewrite: reject raw outside `[0.50,1.00]` with `eta_out_of_range{raw_value}` before clamping.
89. **P0 — Several test fixtures encoded wrong arithmetic or a write-enabled dry-run.** Import asks used the wrong sign difference, S15 mixed nameplate and learned reserves, S71 used 600 s instead of 780 s, and S145 expected migration to `protection_active`. Rewrite: authoritative sign/timing convention, capacity-basis labels and write-free latch.

90. **P0 — Dry-run clearance could deadlock or resume on an orphaned setpoint.** Writes were held pending a neutral hold that only a write could create. Rewrite: after logged command and health check, fenced safety-lane neutralisation writes are permitted while economic writes stay blocked until every pack is verified neutral; all device writes remain forbidden until clearance succeeds.
91. **P0 — The write-free latch lacked a lifecycle outside startup.** Migration, expiry, reload, API, schedule and watchdog paths were undefined. Rewrite: no path can clear or overwrite it except the explicit logged command plus health check; one acceptance case per path.
92. **P1 — Three last contract inconsistencies remained.** Negative discharge could create nonzero `policy_preference_eur` at zero export; the terminal deadband was described both as deductible and as an activation threshold; status-aware flow predicates omitted idle/unknown/hold-flow gaps; invalid micro-session records preceded validation. Rewrite: charging-only preference, deductible deadband in the formula, status-aware exhaustive predicates, and physical validation before `idle_blip`.

93. **P0 — State and latch concepts remained mixed in clearance.** The invariant read on the latch while writes were allowed during clearance. Rewrite: `dry_run_latched` is absolutely write-free; `clearing` is a separate bounded, terminal, operator-entered state; success commits `auto`, failure returns to `dry_run_latched`. Every pack needs two fresh post-fence neutral reports whether or not a hold was written.
94. **P1 — Receipt status gaps and terminal index remained inconsistent.** Unknown/opposite status with small flow had no outcome, hold/unknown truth rows disagreed with precedence, and salvage/penalty/target used different terminal states. Rewrite: exhaustive status-aware predicates with aligned truth table and one `e_N` terminal index for all three terms.

95. **P0 — Clearance evidence had no barrier for already-idle packs.** Post-fence reports were required but only a hold write created a fence. Rewrite: durable clearance-entry barrier generation per pack before any evidence read; all two neutral reports must cite that generation; older reports are `stale_pre_barrier_evidence`.
96. **P1 — `verified` mixed command confirmation with anomaly confirmation.** Anomaly rows set `verified=true`. Rewrite: `verified` is command verification only, anomalies set `anomaly_confirmed=true` and `evidence_kind=confirmed_anomaly`; hold verification requires exactly `(0,0)`. The 30 W boundary rows and degraded-plan power signature were also completed.

97. **P0 — A first boot after upgrade could be permanently parked.** No latch token meant write authority could not be trusted, while no bootstrap or recovery path existed. Rewrite: fresh/legacy-auto/legacy-dry-run token initialization with audit event and atomic commit, malformed-token recovery, and explicit state-scoped protection reporting.
98. **P0 — The gate left no legal persistence path for clearance and domain outcomes.** Only device writes were scoped. Rewrite: disjoint control-plane and device write classes, journal/generation ordering, one-transaction authority commit, and runtime-only `persistence_denied` outcomes while latched/clearing.

99. **P0 — Bootstrap, indirect commands and health text still left authority holes.** Legacy advisory/unknown modes had no audited migration, control-plane records could be misread as commands, queued device work was authorised at enqueue time, and typed-only warnings did not plainly tell a human that protection was absent. Rewrite: exhaustive audited bootstrap, device-only table with bootstrap exception, execution-time gate for all queued/replayed work, and identical prominent dashboard/API health text.

100. **P0 — Missing-token recovery was conflated with legacy migration.** A lost token on a post-token ledger could silently become generation-1 auto. Rewrite: positive pre-token schema evidence plus no initialization event is required for legacy migration; otherwise enter `authority_recovery_required` with logged operator recovery only.
101. **P0 — Closed-gate bootstrap and initialized control-plane writes were conflated.** Rewrite: `AUTHORITY_UNINITIALIZED/INVALID` permits only the non-extendable token+event transaction; `AUTHORITY_INITIALIZED` applies the M5 state machine with control-plane writes in every state and device-only write rules.

102. **P0 — Legacy provenance and sealed bootstrap were still under-specified.** A restored backup could satisfy schema/event evidence, truncated journals could hide latch history, and non-extendable transaction scope was prose only. Rewrite: three-condition provenance test with journal completeness/hash chain, ambiguous history -> operator recovery, and a sealed BootstrapAuthorityTx type with negative capability tests.

103. **P0 — Checkpoint and authority anchor were underspecified.** Checkpoint updates could drift from event appends and a local anchor claimed more provenance than the platform can provide. Rewrite: atomic checkpoint/event transactions, authority-owned checkpoint with typed denial on ordinary append, separate-file anchor with explicit detectable/not-detectable rollback boundary, and universal startup-resolution journal/banner before dispatch after an unprovable restore.

104. **P0 — Restore special-casing and anchor lifecycle were implementable contradictions.** Rewrites: two universal startup resolutions (reconciled/recovery_required) with a banner on every startup because continuity cannot be proven, restore never changes authority, and a two-phase pending/committed anchor with explicit crash-boundary rules.

105. **P0 — Bootstrap gate opened before anchor durability and startup journaling conflicted with invalid authority.** Rewrites: token/event commit → durable anchor → reconciliation → gate open → dispatch; plus a separate append-only startup-resolution record writable in every phase with no authority/device capability.

106. **P1 — Startup-resolution durability had no publication ordering.** Rewrites: append+fsync record, two-phase pending/promoted anchor ref, atomic first-bootstrap anchor creation, typed persistence failures and explicit crash-window outcomes before the gate opens.

107. **P1 — Two bootstrap ordering lists could disagree and directory entries were not durable.** Rewrites: one Exact ordering list covering record fsync, parent-directory fsync, pending ref, single atomic anchor creation with ref, reconciliation, gate and dispatch; chosen option is parent-directory fsync for each first creation.

## Rewrite acceptance rule derived from this audit

A tick, plan, learning pass or maintenance pass is never allowed to end with only an absence. Each
must end in exactly one of: `applied` (with measured evidence), `blocked` (with all binding reasons),
`deferred` (with a retry time and cause), `skipped` (with a named blocker and unchanged measurement
timestamps), or `failed` (with a typed error and escalation). `updatedAt` only moves on a real
measurement; `lastAttemptAt` moves on every attempt; skipped or unreachable packs are per-pack rows,
never a whole-plan delivery failure.
