An acknowledgement can therefore authorize either regime without binding operator intent. Include the regime in the contract, validate required fields, and test missing, empty, and mismatched acknowledgements.

2. **High — `horizon/sum.rs::series_values`: complete redundant sources are double-counted.** `check_category` accepts any full required source, but arithmetic adds every full source in that category. Making the empty redundant import fixture complete changes the per-slot result from `6.0` to `7.0`, although it represents the same category. Define and apply redundant-source selection before summation; test two complete alternatives.

3. **High — `horizon/sum.rs::source_row`: source availability is ignored.** Neither coverage classification nor arithmetic checks `GridSource.available`. An unavailable source with retained finite samples is classified `Ok`, can satisfy required coverage, and contributes values without notice. Treat unavailable sources as unavailable regardless of retained samples, with tests for required, optional, and redundant cases.

4. **Medium — `horizon/sum.rs::series_values`: `OptionalZero` does not consistently contribute zero.** A partially populated optional source receives `SourceOutcome::OptionalZero`, yet its finite samples are still added. The reported outcome therefore disagrees with arithmetic and can silently alter selected slots. Apply the specified optional-zero policy consistently and test an optional source containing both values and gaps.
