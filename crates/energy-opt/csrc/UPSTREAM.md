# Upstream: where this C comes from

`csrc/core_solver.c` is **generated**. It is a line-range copy of the pure-C numeric section of the
old add-on's CPython extension, and nothing in it is edited.

| | |
|---|---|
| Upstream repository | `yazdannl/ha-energy-manager`, release `0.38.8` |
| Upstream file | `energy_manager/app/optimize/_core.c` (1,050 lines) |
| Upstream SHA-256 | `019c1d04194f45e7c527db86532a1f17bfaec7c35226e2eb1586e70e67125894` |
| Extracted ranges | `43-50`, `52-98`, `100-535`, `660-708` (1-based, inclusive) |
| Generated by | `scripts/extract_core.py` (pinned digest; refuses any other source) |
| Generated file size | 540 upstream lines (plus the banner and one `#include`) |

## What each range is

| Lines | Contents | Why it is vendored |
|---|---|---|
| 43-50 | the `CORE_BUILD_SHA` fallback (`#ifndef` / `#define ""`) | the artifact-identity check keeps working when the define is missing |
| 52-98 | `EPS_KW`/`EPS_KWH`, `PV_*`, `CORE_MAX_DIMENSION`, `CORE_MIN_STATES`, `Config` | the constants the sweep is defined in terms of, and the parameter struct |
| 100-535 | `SlotCtx`, `clampd`, `checked_mul`, `insertion_sort`, `build_grid`, `soc_window`, `grid_window`, `make_ctx`, `bounds`, `build_actions`, `interp`, `next_energy`, `wear_cost`, `exact_power`, `slot_cost`, `choose_power`, **`run_solve`** | the whole numeric solver: every expression that decides a plan |
| 660-708 | `validate_slots` | the per-slot domain guard the CPython entry point ran before allocating |

Extraction is line-granular and verified: after writing, the script re-reads the generated file and
compares the payload byte for byte with the concatenation of those ranges, and `--check` fails if the
checked-in file is not current. That is why the ranges include the leading comments of each block —
the goal is a byte-identical copy, not a prettier one.

## What is *not* vendored, and what replaced it

The rest of `_core.c` is CPython glue and was deliberately dropped:

| Upstream | Replaced by |
|---|---|
| `#include <Python.h>`, `PY_SSIZE_T_CLEAN` | `csrc/core_solver.h` (`<math.h>`, `<stdint.h>`, …) |
| `parse_config` (dict → `Config`) | `core_adapter.c::map_params` + `eo_core_check_config` and the typed Rust `Config` |
| `to_doubles` (sequence → `double[]`) | the flat C ABI's arrays, validated in Rust *and* in `energy_opt_ffi.c` |
| `core_solve` (grid, allocation, dict) | `energy_opt_ffi.c::eo_solve` (same order: validate → grid → coarsen → allocate → sweep) |
| `dict_set_float/long`, `PyList_*`, `PyBytes_*` | the `eo_result` struct (one C-owned arena, released by `eo_free`) |
| `Py_BEGIN_ALLOW_THREADS` | nothing to release: the ABI is plain C and called from Rust |
| `PyInit__core`, `build_sha` module constant | `eo_build_sha()` |

Two call sites inside the extracted text still say `PyErr_SetString` / `PyErr_Format`
(`build_grid` and `validate_slots`). They are *not* edited: `csrc/core_solver.h` defines those two
names as macros onto a one-slot error buffer (`eo_core_note_error` / `eo_core_format_error`) in
`core_adapter.c`, which the ABI reports through `eo_last_error()`. Defining two names was preferred
over touching the vendored lines, because every change to those lines is a change to the solver.

## The build

`build.rs` compiles `csrc/core_adapter.c` (which includes `core_solver.c`, so the extracted
`static` helpers stay exactly as upstream wrote them) and `csrc/energy_opt_ffi.c` with:

```text
gcc -O3 -ffp-contract=off -fno-fast-math -DCORE_BUILD_SHA="<sha16>"
```

* `-O3` is the level the add-on shipped.
* `-ffp-contract=off` is mandatory: FMA contraction changes rounding, which flips near-tie argmins
  and breaks the differential.
* `-fno-fast-math` keeps every expression the IEEE operation the reference performs.
* `-Wno-unused-function` only silences helpers that the dropped Python entry point used.

## The digest chain

1. `scripts/extract_core.py` pins the upstream `_core.c` SHA-256 and refuses anything else.
2. `build.rs` frames `core_solver.h`, `core_solver.c`, `core_adapter.c`, `energy_opt_ffi.c` (path,
   length, bytes) and hashes them with SHA-256.
3. The first 16 hex characters become `-DCORE_BUILD_SHA`, so the C artifact carries the digest of
   the exact sources it was compiled from; the full digest is baked into the Rust binary as
   `EO_CORE_SOURCE_SHA256`.
4. `energy_opt::verify_core_build()` re-hashes the sources `include_bytes!`d into this binary and
   compares both digests on the first solve. A stale, copied or cached object file cannot pass (the
   same rule as `_fast.stale_reason`, which the old loader enforced with mtimes).

## Evidence that the copy is faithful

* `crates/energy-opt/tests/fixtures/parity.json` — 20 deterministic scenarios generated by
  `scripts/gen_parity_fixtures.py` from the unchanged Python reference `dp._solve_once_numeric`:
  objective, path, windows, state grid and the whole value function at 1e-9, decisions exactly.
* `crates/energy-opt/tests/oracle.rs` — the independent Rust brute-force DP agrees with the C core
  on the same scenarios, every `slots × states` argmin included.
* `crates/energy-opt/tests/parity.rs::test` run on every `cargo test`.

Regenerate after a genuine upstream change:

```sh
python3 scripts/extract_core.py            # re-extract (refuses a different upstream digest)
python3 scripts/gen_parity_fixtures.py     # re-pin the fixtures against the reference
cargo test -p energy-opt
```
