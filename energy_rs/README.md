# Energy RS

Home Assistant add-on for [energy-rs](https://github.com/yazdannl/energy-rs).

## Add this repository to Home Assistant

Settings → Add-ons → Add-on store → ⋮ → **Repositories** → paste
`https://github.com/yazdannl/energy-rs`, then install **Energy RS** (`energy_rs`).

* `ingress: true` on port 8099: the UI opens inside Home Assistant, no exposed port.
* `homeassistant_api: true`, `hassio_api: false`: Core REST/WS only, nothing from the Supervisor API.
* Defaults: `mode: dry_run`, `log_level: info`. Options are read by the binary at start; changing
  them needs an add-on restart.

## Modes

| mode | behaviour |
|---|---|
| `advisory` | compute and store plans only |
| `dry_run` | full pipeline including safety clamps; intended writes are logged, nothing is sent |
| `auto` | actually writes setpoints to the batteries |

`auto` is never the default: install side by side, watch `dry_run` for a day and compare with the
old add-on's dispatch before switching.

## Building the image

The Dockerfile expects the repository root as build context (the Rust workspace and `web/` live
there):

```bash
npm --prefix web run build          # real UI into web/dist
docker build -f energy_rs/Dockerfile -t energy-rs:0.1.0 .
```

Home Assistant's Supervisor builds an add-on with the add-on folder as context, so P10 either
publishes a prebuilt multi-arch image (`image:` in `config.yaml`, preferred) or stages the workspace
into the published add-on folder.

`web/dist` is embedded at compile time. If it is not built, the checked-in placeholder
`web/dist/index.html` is what ships — the API works, the UI shows a "not built yet" page.

## Files

| file | purpose |
|---|---|
| `config.yaml` | add-on manifest (slug, arch, ingress, options/schema) |
| `Dockerfile` | `rust:1-bookworm` builder → `debian:bookworm-slim` runtime (ca-certificates, tzdata) |
| `run.sh` | entrypoint; `exec`s `/usr/local/bin/energy-server` so SIGTERM reaches the binary |
| `icon.png`, `logo.png` | store art, regenerated by `scripts/make-icons.py` |
